## Release constraints

- No Developer ID signing identity or notarization profile is available on this Mac. The ZIP is ad-hoc signed, like 0.1.10; first-launch Gatekeeper behavior remains the same.
- The 0.1.10 host's same-user socket risk remains for running old terminals. The app cannot move their pty masters to the new host.
- The next release must use a new terminal-host socket version and pin the published 0.1.11 CDHash `dba56a1fb25fe3399fa03e6bfcfffe9e05497972` for v3 session recovery. Reusing v3 with a different binary would disconnect running v3 sessions.
- The currently installed local 0.1.11 test build has CDHash `9ec7328c9d72e84ae3e35a2a456b0f8ba3c3d559`, different from the release ZIP. It will not auto-update to an equal version. If its v3 host gains terminals before a later update, preserve that host separately or explicitly support this CDHash; at package preparation time it had no child shells.
